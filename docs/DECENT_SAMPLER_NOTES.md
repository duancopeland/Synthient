# Decent Sampler (.dspreset / .dslibrary) support

Free Pianobook / Decent Sampler libraries (tape pads, cassette pianos, Rhodes, old synths)
ship as a folder with one or more `.dspreset` files (XML) plus WAV/FLAC/AIF samples, or
as a `.dslibrary` (a zip of the same thing). Synthient does not read `.dspreset`
directly; two tools convert them to SFZ for our own engine (`Source/Sampler/SfzInstrument.cpp`).

| Tool | What it does |
|---|---|
| `library/tools/dspreset_to_sfz.py` | Converts one `.dspreset`, a `.dslibrary`, or every preset in a folder. Writes `<same folder>/<same name>.sfz`. |
| `library/tools/index_user_instruments.py` | Walks the user instrument folder, converts everything, collects all `.sfz` (converted or hand-dropped) and writes `user_index.json`. |

## How to run

```
set PY=D:\ClaudeDAW\analysis\.venv\Scripts\python.exe
%PY% library\tools\dspreset_to_sfz.py "C:\path\Tape Piano\Tape Piano.dspreset"
%PY% library\tools\dspreset_to_sfz.py "C:\path\Cassette Keys.dslibrary"
%PY% library\tools\index_user_instruments.py            (default folder below)
%PY% library\tools\index_user_instruments.py "D:\My Samples" --force
```

Default folder: `%USERPROFILE%\Documents\Synthient\Instruments`. Only the Python stdlib is needed.

Rules:
- Originals are never modified. The `.sfz` goes next to the `.dspreset` so the relative
  sample paths stay valid (FLAC/AIF/OGG paths are kept as-is; the engine decodes them).
- A `.dslibrary` is extracted to a sibling folder with the same base name. If that folder
  exists it is not re-extracted. Archive entries escaping the folder are refused.
- An existing `.sfz` is only overwritten if its first line is the marker
  `// Generated by dspreset_to_sfz.py` (or `--force`), so a hand-made SFZ with the same name is safe.
- Re-running is idempotent.

## user_index.json

Same shape as `library/index.json` `instruments` entries, without `regions`:
`name, family, articulation, source, license, sfz, range`, with
- `sfz`: absolute path; `source`: `"User"`; `license`: `"see library folder"`.
- `range`: min `lokey` .. max `hikey` over non-release regions (`sfzlib.region_keys`).
- SFZ files with no playable regions (only release / `*sine` / CC-triggered regions) are skipped.
- `family` is guessed from folder + file name keywords, using the vocabulary already in
  `index.json`: `keys, synth (pads/tape/old synths), strings, guitar, bass, drums, percussion,
  brass, woodwinds, choir (vocal), fx, other`. `articulation` defaults to `sustain`
  (`kit` for drums; staccato/pizzicato/etc. from the file name).
- `name` is the SFZ base name, plus `(parent folder)` when that differs and adds information.

## Format mapping

Attributes inherit `<groups>` -> `<group>` -> `<sample>` (most specific wins), except the
volume and tuning attributes, which are summed across levels (see below).

| Decent Sampler | SFZ (our engine) | Notes |
|---|---|---|
| `<group enabled="false">` | (skipped) | counted in warnings |
| `path` | `sample` | backslashes -> `/`; written last on the line (paths may contain spaces) |
| `rootNote` | `pitch_keycenter` | missing -> `loNote`, else 60 (warned) |
| `loNote` / `hiNote` | `lokey` / `hikey` | default 0 / 127. Note names accepted with C4=60 (warned; DS normally uses numbers) |
| `loVel` / `hiVel` | `lovel` / `hivel` | clamped 1..127 |
| `start` / `end` | `offset` / `end` | sample frames |
| `globalTuning` + `groupTuning` + `tuning` | `tune` (cents) | semitones (float) x 100, summed |
| `volume` (groups, group, sample), `globalVolume`, `groupVolume` | `volume` (dB) | `"-3dB"` style taken as dB; a plain number is a linear gain -> 20*log10(x). Levels multiply (dB summed) |
| `pan` | `pan` | -100..100, same scale |
| `ampVelTrack` (0..1) | `amp_veltrack` (x100) | only emitted if present (engine default 100) |
| `pitchKeyTrack` (0..1) | `pitch_keytrack` (x100) | |
| `attack` | `ampeg_attack` | seconds |
| `sustain` (0..1) | `ampeg_sustain` (x100) | |
| `decay` | `ampeg_decay` | converted, see ADSR below; omitted when sustain is 1 |
| `release` | `ampeg_release` | seconds; **if absent we emit 0.1 s** (engine default 1 ms clicks; DS default assumed ~0.1 s, unverified) |
| `loopEnabled="true"` + `loopStart`/`loopEnd` | `loop_mode=loop_continuous`, `loop_start`, `loop_end` | if no points given, the engine uses the WAV's embedded loop (or falls back to no loop if invalid) |
| `loopEnabled="false"` | `loop_mode=no_loop` | |
| loop points without `loopEnabled` | (nothing) | warned; DS treats looping as off by default (assumption) |
| `trigger` attack/release/first/legato | `trigger` | same names |
| `seqMode="round_robin"` + `seqLength` + `seqPosition` | `seq_length` / `seq_position` | per region, so counters are per key range in our engine |
| `seqMode="random"` / `"true_random"` | `lorand` / `hirand` | position p of n -> [(p-1)/n, p/n). `random` (no-repeat) becomes plain random (warned) |
| `seqMode="always"` | (nothing) | default |
| `tags` | `group` | first tag of the sample (sample `tags` override group `tags`) -> a number; mapping printed in the SFZ header comment |
| `silencedByTags` | `off_by` | first tag only; a region with no tag gets its own group (1000+n) so it can be choked |
| `silencingMode` fast/normal | `off_mode` fast/normal | default fast |

### ADSR mapping

Decent Sampler's `decay` is the time to go from the peak to the sustain level (treated
here as a JUCE-style ADSR). Our engine's `ampeg_decay` is SF2-style: an exponential fall
that would drop 100 dB in `ampeg_decay` seconds and stops at the sustain level. The
converter picks the SF2 time so the fall reaches the sustain level after the DS decay time:

```
drop_dB     = clamp(-20*log10(sustain), 1, 60)    (sustain 0 -> 60 dB, i.e. "silent")
ampeg_decay = min(100, decay * 100 / drop_dB)
```

Example: decay 1 s, sustain 0.5 (-6 dB) -> `ampeg_decay=16.61`. Decay 0.5 s to sustain 0
-> `ampeg_decay=0.833` (-60 dB at 0.5 s). The curve shape still differs (an exponential
sounds shorter than a linear fall over the same time); acceptable for pads and pianos.

## Ignored (counted in the warnings list)

- `<ui>`, `<effects>` (reverb, delay, filters, chorus...), `<modulators>` (LFOs, envelopes),
  `<midi>` (CC bindings), `<tags>` (tag-level volume/polyphony), `<noteSequences>`, `<buses>`.
  Many Pianobook presets rely on a built-in reverb/tone knob, so the converted sound can be
  drier/brighter than in Decent Sampler; add effects on the track instead.
- Attributes: `loopCrossfade` (no crossfade looping in our engine), glide/legato settings,
  envelope curve shapes, per-group filter/effect attributes, anything unknown.

## Limitations and assumptions (from memory of the DS docs; not verified against a real library)

- Summing volume/tuning across `<groups>`/`<group>`/`<sample>` assumes DS applies each level
  as its own gain/offset. If a library sounds too quiet, this is the first suspect.
- A plain-number `volume` is treated as linear (1.0 = unity); `"dB"` suffix as decibels.
- Note names (if any) are read as C4 = 60; DS may use another octave convention.
- Round-robin counters are per region (key range) in our engine, DS's are per group.
- Multiple tags per sample collapse to the first one (SFZ has one `group` per region).
- Release-trigger regions get the inherited ADSR like any other region; DS-specific release
  options are not converted.
- Encrypted/commercial Decent Sampler formats are not supported.

## Self-test

`run_test.py` (in the session scratch folder, not in the repo) generated sine samples
(two velocity layers, a round-robin pair, a random pair, a looped pad with a space in its
file name, a release sample, open/closed hi-hat choke, a disabled group), a `.dspreset`
plus a `.dslibrary` zip of it, a native SFZ and a release-only SFZ; ran both tools; and
checked every region and opcode with `sfzlib.parse`, the index entries, that originals are
untouched, and that a second run is idempotent. All checks passed.
